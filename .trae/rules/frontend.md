# 前端专项规则

> 前端是**单人项目里最容易被 AI 过度生产的部分**。
> AI 会兴高采烈地给你加动画、加暗色主题、加响应式、加 20 个组件——然后你的时间就没了。
> 所以这里的第一条规则是"少做"。

## 一、只做被批准列出的页面

- 只实现 `docs/tasks.md` 里明确列出的页面。**不要"顺手"新增页面、组件库、状态管理方案、主题系统。**
- 当前阶段（V-1）**没有任何前端页面**。若我让你写页面，说明我已经进入 V0.1，并且只做三页：
  知识库列表页、文档上传页、问答页。
- 每新增一个依赖（UI 库、图标库、图表库、表单库、请求库），按 R12 先说理由。

## 二、技术栈与调用约定

- Next.js 15 App Router + TypeScript + Tailwind + shadcn/ui。**不要引入第二个 UI 框架。**
- **所有后端调用集中在一个文件**（`lib/api-client.ts`）：统一处理 baseURL、错误码 → 用户可读文案、`snake_case` → `camelCase` 映射。
  **禁止在组件里裸写 `fetch`。** 否则后端改一个字段名，你要改 20 个地方。
- 类型定义不要手写：从 `docs/openapi.yaml` 生成或对齐，字段名与后端逐字一致。

## 三、必须正确展示的三种特殊状态（最容易漏）

| 状态 | 前端必须做什么 | 为什么 |
|---|---|---|
| **拒答**（`refused: true`） | 展示中性提示（"根据现有资料，无法回答"），**不是红色报错、不是空白** | 误当成错误会让用户以为系统坏了，反复重试 |
| **降级**（`degraded: true`） | 在答案旁显示一条轻提示："当前为降级模式，答案可能不完整" | 用户有权知道质量下降了 |
| **引用** | 每条答案下方列出引用卡片：文档名 + 页码 + 原文片段，**可点击展开** | 引用是这套系统建立信任的唯一手段，不能藏起来 |

## 四、不写的东西（V0.1 阶段）

- 不做登录页、权限管理页、用户中心（V1 才做）
- 不做自动重试的轮询动画、不做骨架屏以外的复杂加载态
- 不做暗色主题、不做多语言、不做移动端专门适配（先保证桌面可用）
- **不做"看起来专业"的空壳页面**——只有按钮没有后端的页面比没有页面更糟，会让你误以为已完成

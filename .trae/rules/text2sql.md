# Text-to-SQL 通道专项规则（V2）

> 只在这几类文件被打开/引用时生效。
> 这些规则的共同点：**违反了不会报错**——
> 程序照常返回 200，用户拿到一个格式漂亮的数字，**而没有任何机制能发现它是错的。**
> 文档通道答错时用户点开引用就发现了；这条通道不会。

## 零、最重要的一条

**这个通道里，"错得静默"是默认状态，"错得可见"才是需要刻意设计出来的。**
所以下面每一条规则的本质都是同一件事：**把静默失败转成可见失败**（拒答、报错、标注范围）。

## 一、语义层是唯一的对象来源

- 表、列、指标口径**只能来自 `config/semantic_layer.yaml`**。
  模型生成了未声明的表/列 → **校验层拒绝执行 → 拒答**。
  **禁止"猜一个近似字段"**：`annual_leave_days` 不存在时猜 `leave_days`，
  会返回一个看似合理的数字——**这是本通道最危险的单一行为**。
- 枚举值**必须**用语义层里的 `enum` 映射。
  中文值直接写进 SQL（`category = '培训'`）→ 返回 0 行 → 系统会说"没有培训支出"。
  **0 行比报错更危险，因为它看起来像个结论。**
- 时间说法（"上个月"/"本季度"）**必须**由代码按 `time_phrases` 解析成确定区间，
  **禁止**让模型自己算日期（跨年、跨月边界一定会算错）。
- 语义层改动必须单独提交，类型用 `semantic:`。改动会产生新的 `version`，
  而版本会写进回答与日志 —— 否则无法解释"同一个问题为什么数字变了"。

## 二、路由：默认回落文档通道

- 路由**必须**是显式的可测组件，**不是**提示词里一句"请判断用户想查什么"。
- **默认通道是 `doc`**。`confidence` 低于阈值（0.75）→ 回落 `doc`。
  理由：文档通道有可靠的拒答机制；SQL 通道一旦产出数字就没人能判断对错。
  **不确定时，选那个会承认自己不知道的通道。**
- SQL 通道"生成或校验失败"→ 允许改用文档通道**重试一次**，并在响应里记 `channel_attempts`。
- **混合问题（`hybrid`）只做并列展示，禁止自动融合。**
  不做 Agent、不做多工具自主编排（`docs/adr/0005`、`docs/adr/0009` 方案 C 否决）。

## 三、SQL 安全：五道闸门，任何一道不过就不执行

| # | 闸门 | 硬要求 |
|---|------|--------|
| 1 | 只读账号 | 该连接的数据库账号**只有 `SELECT`**。**绝对禁止**为提高便利性加写权限 |
| 2 | 语句结构 | 用**解析器**（如 `sqlglot`）校验，**禁止用正则**（注释/大小写/别名能绕过）。只允许单条 `SELECT` |
| 3 | 对象白名单 | 逐项比对语义层；命中 `denylisted_columns`、`pg_*`、`information_schema` → 拒答 |
| 4 | 强制 LIMIT | 缺 LIMIT 或超上限 → 强制改写为 `max_rows`，并置 `truncated=true` |
| 5 | 超时配额 | `statement_timeout` 生效；单请求最多 1 次执行；**失败不重试**（重试会放大负载） |

- **校验必须在执行前**，不能只在生成时提示模型。模型听不听不重要，**不听就执行不了**。
- **绝对禁止**把动态生成的 SQL 字符串用 `f-string` / `%` 拼进已有 SQL 模板——
  参数必须走参数化绑定（`$1` / `%s`）。
- 校验失败必须记 `reject_reason`（枚举见 `docs/data-model.md` 2.15），**不是**静默丢弃。
  它是"语义层该补什么"的唯一数据来源。

## 四、权限：与文档通道同源

- SQL 通道的可见性过滤**必须复用文档通道同一段权限解析代码**，
  把 `user_scope` 翻译成业务表的 `scope_column` 条件，**拼进 SQL 的 WHERE**。
  两条独立的权限实现迟早会漂移，而漂移的形态是
  "**文档里看不到、SQL 里能算出来**"——比文档越权更隐蔽。
- `nl2sql_logs.scope_snapshot` 与 `query_logs.scope_snapshot` 存**同一个值**。
- 缓存 key 除权限指纹外，**还必须含 `semantic_layer_version`**（否则改口径后用户在拿旧数字）。

## 五、聚合范围：禁止静默跨范围（本通道唯一不可接受的失败）

- 每个指标**必须**在语义层声明 `scope_mode: own | global`，**无默认值**。
- `scope_mode: own` 的答案**必须**在文案里标注范围，例如：
  `基于你有权访问的 312 条记录，上个月平均报销 ¥1,024.60`。
  **这句话不是客套**——它是用户唯一能察觉"这不是全公司数字"的线索。
- `scope_mode: global` 必须由业务方显式列入白名单。**白名单从空开始、按需增加。**
  定漏了会拒答（可见），定多了会越权（**不可见**）——所以宁可漏。
- **禁止**"静默做行级过滤后不标注范围"。它会产生一个"用正确方法得出的错误结论"，
  而用户会拿它去汇报。

## 六、输出：SQL 必须展示，数字不得自行计算

- 回答**必须**附带生成的 SQL 与结果集（前端可折叠）。理由有二：
  **可审计**（数字怎么来的用户能看到）、**可纠错**（口径错了用户会比你先发现）。
- **数字只能来自执行结果**（`AGENTS.md` R6 的扩展）。
  模型**禁止**自行相加、相减、换算单位、四舍五入、补"约/大约"。
  要"不含税额"就**新定义一个指标**，不许在 SQL 里手动除。
- 拒答**沿用同一句固定句式**（R5）：`根据现有资料，我无法回答这个问题。`
  **不要**为 SQL 通道另造一句（会脱离统一统计）。
  原因码通过结构化字段 `refused_reason` 表达：
  `doc_no_match | schema_no_match | scope_denied | unsafe_sql`。
- 执行超时/被拦 **必须抛结构化错误码**，**禁止**返回 0 行冒充"没有数据"（R7）。

## 七、评估

- **比结果集，不比 SQL 文本。** 两条完全不同的 SQL 可能结果一致；
  一条只差一个条件的 SQL 文本相似度很高但少算一半。**文本相似度与正确性无关。**
- 比对规则：**列序无关、行序无关、列名不参与比对**；数值列按相对容差 `1e-6`。
- 必须在**固定种子数据集**（`evals/sql/seed.sql` → 临时库 → 跑完销毁）上评估。
  对着生产库跑评估 = "今天 100 分、明天 60 分"。
- **路由准确率与执行准确率必须分区报告**，不与文档通道的指标混算。
- 归因时先看 `reject_reason` 再下结论：
  `unknown_object` 通常意味着**语义层缺声明**，而不是"模型不行"。

## 八、绝对禁止（Reject List）

- ✗ 给 SQL 通道的连接账号任何写权限（DDL / DML / TRUNCATE / GRANT）
- ✗ 用正则做 SQL 对象白名单校验（必须用解析器）
- ✗ 让模型自由引用未在语义层声明的表 / 列，或用"近似字段"代替不存在的字段
- ✗ 用 `f-string` / `%` 拼接动态 SQL（必须参数化绑定）
- ✗ 静默做行级过滤而不在答案里标注范围
- ✗ 让模型自行计算 / 换算 / 四舍五入结果数字
- ✗ 把 SQL 通道做成 Agent / 多工具自主编排
- ✗ 混合问题自动融合成一个答案（只允许并列展示）
- ✗ 在明细层返回未经聚合的行级数据（明细导出 = 把权限模型推倒）
- ✗ 在文档通道的评估报告里混入 SQL 通道的指标

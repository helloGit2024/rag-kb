1. 开发者是**一个人**（懂 RAG 算法，不懂前端后端）+ 你。没有团队、没有专职运维、没有第二个人 review。

## 2 · 技术栈（锁定，禁止擅自更换）

| 层 | 选型 | 为什么（一句话） |
|----|------|----------------|
| 前端 | Next.js 15 + TypeScript + Tailwind + shadcn/ui | 资料最多，遇到问题我自己能搜到 |
| 后端 | Python 3.12 + FastAPI + Pydantic v2 | 与 RAG 生态同语言 |
| 关系库 + 向量 | PostgreSQL 16 + pgvector（HNSW） | 元数据与向量同库，权限过滤能在一条 SQL 里完成 |
| 关键词检索 | PostgreSQL `tsvector` + `pg_trgm` | 不额外维护一个 ES 集群 |
| 嵌入 | bge-m3（本地部署） | 数据不出内网，无调用费 |
| 生成 | 经 LLM 网关路由（小模型主力 + 大模型兜底） | 成本可控且能故障降级 |
| 重排 | bge-reranker-v2-m3 | 与嵌入同源，部署一套 |
| 缓存 / 队列 | Redis 7 | 一个组件解决三件事 |
| 对象存储 | MinIO（S3 兼容） | 可自建，以后迁 OSS 不改代码 |
| 部署 | Docker Compose 单机 | 单人不能用 K8s |
| 迁移 | Alembic | 迁移必须可回滚 |

**本表之外的技术一律不引入。** 需要更换时：先更新本文件 + `docs/architecture.md` + 新写一份 ADR，并等我同意。

## 3 · 目录约定（谁能放什么，一句话）

| 目录 | 放什么 | 禁止 |
|------|--------|------|
| `app/api/` | HTTP/SSE 路由 | 写业务逻辑、直接查库 |
| `app/services/` | 业务编排（检索、生成、权限判定） | 写 SQL |
| `app/repos/` | 数据访问 | — **这是唯一允许出现 SQL 的一层** |
| `app/schemas/` | Pydantic 请求/响应模型 | 写逻辑 |
| `app/prompts/` | 提示词模板（`.md`，版本化） | **把提示词写在 `.py` 里** |
| `app/core/` | 配置、日志、鉴权、LLM 网关 | 写业务规则 |
| `app/core/providers/` | 各厂商模型适配器（chat / embed / rerank） | 业务代码里出现"判断是哪家厂商"的 if |
| `app/workers/` | 离线任务（解析、向量化、评估） | 被在线请求同步调用 |
| `app/eval/` | 评估编排（数据集校验、对照检索、候选归类、报告） | 写入归因**结论**（只能人工写，R15） |
| `app/services/nl2sql/` | V2 SQL 通道：生成 / 校验 / 执行（**唯一允许动态 SQL 的例外**） | 绕过五道闸门；拼接未参数化的 SQL |
| `config/` | RAG 策略参数、**语义层**（走 Git，改动需 diff） | 把密钥 / DSN 写进配置（只写环境变量名，R1） |
| `tests/` | 单元 + 集成测试 | 写"永远通过"的空测试 |
| `evals/` | 评估集、归因手册与说明 | **为让评估通过而删题、改标准答案** |
| `samples/` | 演示 / 手测语料（如 curl 演示的部门级文档） | 当评估集用（评估题与评估语料归 `evals/`） |

## 4 · 硬规则（每条都可判定；违反后果写在括号里）

- **R1 密钥外置**：任何密钥/密码/内网地址不得写死在代码里，必须走环境变量或 `.env`；`.env` 不进版本库，但维护 `.env.example`。（泄露 = 真实损失）
- **R2 权限过滤下沉 SQL**：文档可见性条件必须写在 SQL 的 `WHERE` 里。**禁止"先查 Top-20 再在 Python 里筛掉无权访问的"**。（越权泄露 + 召回崩塌，双重事故）
- **R3 缓存 key 含权限指纹**：问答/检索缓存的 key 必须包含**可见范围的指纹**（`scope_keys` 的哈希），禁止只用问题文本。（A 部门命中 B 部门的答案，极难复现）
- **R4 提示词独立成文件**：全部放 `app/prompts/*.md` 并带版本号；改提示词单独提交，类型用 `prompt:`。（否则无法回溯"哪一版指标最好"）
- **R5 拒答句式固定**：拒答必须且仅输出 `根据现有资料，我无法回答这个问题。`，同时结构化字段置 `refused=true`。（自由措辞的拒答无法统计，等于放弃幻觉监控）
- **R6 数字原文照抄**：金额、日期、数量、比例必须原文照抄，禁止四舍五入、换算单位、加"约/大约"。（"1204 万"写成"约 1200 万"是数据错误，比答不出来严重）
- **R7 显式失败**：出错必须抛异常并返回结构化错误码。**禁止 `except: pass`、禁止返回空列表藏问题、禁止默认值兜底**。（错得悄无声息，无法定位起始时间）
- **R8 数据库变更拆两次发布**：先加字段（可空）→ 代码兼容新旧 → 稳定后再清理旧字段。**禁止同一次改动里"删字段 + 改代码"**。（代码能回滚，数据不能）
- **R9 改动范围最小化**：动手前先列"要改哪些文件、每处改什么、为什么"，等我确认。不得顺手改我没让你改的地方。
- **R10 在线/离线链路隔离**：解析、向量化、批量评估必须走 `app/workers/` + 队列，**禁止在 HTTP 请求里同步执行超过 3 秒的重活**；离线任务并发用信号量限制。（一人上传 300 页 PDF 会卡死全站）
- **R11 模型调用必经网关**：业务代码不得直接调模型接口，一律走 `app/core/llm_gateway.py`（它负责重试、熔断、超时、降级、Token 记账）。（否则没有成本统计，也没有故障降级）
- **R12 新依赖先申请**：引入任何新依赖前，用一句话说明"它解决什么问题、现有技术栈为什么做不到、代价是什么"。（单人维护不了多套抽象层）
- **R13 评估集不可为通过而改**：删题、改标准答案必须写理由并单独提交，类型用 `eval:`。（标尺被污染，你就不再是在优化系统）
- **R14 评估必须可复现**：每次评估记录 `git_commit` + `config_snapshot`；跑前校验数据集 checksum，不一致**拒绝开始**。配置快照不同的两次运行**不得**直接宣称"进步了"。（无法解释的数字比没有数字更危险）
- **R15 归因结论只能人工写入**：机器只能产 `attribution_candidate`；`attribution_confirmed` 只能由我写，**且必须带判定依据**。未确认的不计入任何统计。（否则你会按一个 60% 准确率的分组去修没坏的地方）
- **R16 评估题目写入边界**：题目本体是**文件**，禁止做成数据库 CRUD；线上失败沉淀成考题（promote）**只能产候选**到 `evals/pending/`，**禁止**直接写进 `evals/golden_set.yaml`。（系统能自己出题自己定答案 = 门禁静默失效）

## 5 · 当前版本范围（**每进入新版本由我更新本节**）

**当前：V1 试点可用。** V0.1 已于 2026-10-28 通过退出门禁（run 344：拒答 0.90 / 误拒 0.095 /
Recall@5 1.0 / MRR 1.0 / 忠实度 0.9375；注入测试集 8/8）。V0.1 已完成的事不再列进下面，别重做。
质量对比基线：`eval_runs` 标记基线 run 97（同数据集 v1.0.3），V0.1 出口实测 run 344。

### ✅ V1 要做的

1. **检索质量升级（最高杠杆）**：混合检索（向量 + `tsvector`，不装 ES）、RRF 融合、
   bge-reranker-v2-m3 重排（Top-20 → Top-5）、查询改写（规则 + 小模型）
2. **权限与合规**：RBAC（4 角色）、审计日志（只追加不可改，含 who/when/what/target/result）、
   文档删除全链路清理（AC-19）、登录 + JWT
3. **稳定性与运维**：SSE 流式（含降级）、模型降级 + 全局降级开关、成本预算硬上限、
   Prometheus + Grafana + 3 条告警、一键回滚脚本（< 5 分钟，真实演练过）
4. **反馈与迭代闭环**：👍👎 落 `feedback`（候选）→ 人工确认进 `badcases`（结论）；
   "答不出来的问题排行"页面；评估数据集元数据接口 + 异步评估任务 + 逐条结果 +
   `changed_only` 回归对比；归因闭环；线上失败 promote 到 `evals/pending/`；
   评估集扩到 100+ 条；报告导出 CSV / XLSX
5. **存储升级**：向量库仍为 pgvector（不迁移）；数据库每日备份 + MinIO 快照
6. **生成与拒答质量（V0.1 实证驱动，T81—T83）**：引用绑定校验修复（扩至全部检索块或自动重绑，
   Q008/Q030）；时间语义代码级解析（Q027）；澄清式拒答（固定前缀 + 一句澄清，Q029）

### ❌ V1 明确不做

- PDF / Word / Excel / OCR（V2）、可视化策略配置（策略写配置文件，不做界面）
- GraphRAG / Self-RAG / Agentic RAG
- 评估可视化面板、"知识库 × 策略 × 模型"任务选择器、自动归因分类器（`docs/adr/0008`）
- 服务端 PDF 导出（改用浏览器打印，`docs/adr/0008`）、K8s、微服务拆分、SSO、行级权限
- **SQL 通道与语义层（V2，`config/semantic_layer.yaml` 与 `evals/sql/` 只作参考、不得接入）**

> 上面 ❌ 的条目，**即使你觉得"顺手就能加上"，也不要加**。想加先问我。

V1 的 13 条退出门禁见 `docs/releases.md` → `## V1｜试点可用版本`（本文件不重复，避免不一致）；
任务清单见 `docs/tasks.md` → `## 三、V1 试点可用`（T40—T70 + T81—T83）。

**进入新版本的 3 步**：① 找 `docs/releases.md` 新版本一节；② 把 ✅/❌ 摘成短句替换本节两段；
③ 上一版已完成、且新版不再禁止的项从 ❌ 删掉。**永远不要**只改本文件不改 `docs/releases.md`
—— 两份不一致时，AI 会挑一个它更喜欢的执行。

## 6 · 交互协议（我要求的工作方式）

1. **一次只做一个任务**（`docs/tasks.md` 里的一个 ID）。做完停下等我确认。
2. 动手前先给方案：改哪些文件、每处改什么、为什么。**我同意后再写代码。**
3. 验证优先用 `make` 命令（`make test` / `make lint` / `make eval`），不要只口头说"应该没问题"。
4. 我贴报错给你时，**按报错定位，不要重写整个文件**。
5. 任务完成后按固定格式汇报：
   - **我做了什么：**
   - **改了哪些文件：**
   - **怎么验证（我要做什么才能确认它对）：**
   - **我不确定的地方：**
6. 若发现 `docs/` 内部自相矛盾，**指出来**，不要自己挑一个执行。
7. 不要主动"顺手优化"我没让你改的代码。
8. 单次改动超过 8 个文件时**停下**，告诉我该拆任务了。

# RAG 链路专项规则

> 本文件只在这几类文件被打开/引用时自动生效。
> 这些规则的共同点：**违反了不会报错，只会悄悄降低质量**——所以必须写下来。

## 一、分块（Chunker）

- **禁止**在分块结果里切断句子。切割优先级：段落 → 句子 → 字符。只有在前两者都做不到时才允许硬切字符。
- 每个 chunk 必须携带完整元信息：`doc_id`、`page`（或段落序号）、`char_start`、`char_end`、`chunk_index`、`scope_key`、`strategy`、`strategy_version`。
- **块大小与重叠是"实验参数"，不是魔法数字**。修改 512/64 这两个值必须：
  ① 在 `docs/experiments/` 下写一份实验记录；② 全量重建向量；③ 跑 `make eval-compare`。
- 分块策略变更必须整体重新向量化——**禁止"只对新文档用新策略"**，那会让同一个知识库里存在两种分布，检索结果不可解释。

## 二、检索（Retrieval）

- **权限条件必须在 SQL 里**（`AGENTS.md` R2）。检索函数签名必须显式接收 `user_scope`，**不允许有"不传权限"的默认重载**——参数不存在，代码就写不出越权查询。
- 权限过滤必须在**向量检索的同一句 SQL 内**完成。禁止模式：
  ```python
  # ✗ 绝对禁止
  rows = vec_search(q, top_k=20)
  rows = [r for r in rows if r.scope_key in user.scopes]   # 越权数据已进入内存与日志
  ```
- 检索层只返回候选，**不做阈值判断、不做拒答判定**——那些属于生成层，混在一起会让你无法区分"没找到"和"没答好"。
- 所有检索耗时必须分段埋点：`embed_ms` / `vector_search_ms` / `bm25_ms` / `fusion_ms` / `rerank_ms`。

## 三、融合与重排

- RRF 融合的 `k` 值（默认 60）与各路 `top_k` 必须来自配置，**禁止硬编码**。
- 重排只做"重排序"，**不得增删候选**（不允许重排阶段过滤掉检索给的结果，否则归因会乱）。
- 一次只改一个变量：**先上融合、再上重排，分开做、分开评估**。同时改两个，指标变了但你说不出是谁的功劳。

## 四、生成（Generation）

- 提示词必须从 `app/prompts/*.md` 读取，**不得内联在 Python 里**（R4）。
- 提示词模板里必须包含三段固定结构：
  1. **角色与边界**："只依据下方资料作答"
  2. **资料区**：带编号的 chunk 列表（`[1]`、`[2]`…）
  3. **拒答指令**：无充分依据时输出固定句式（R5）
- **引用编号由程序注入，不得让模型自己编号。** 生成后必须做"引用回绑"：把 `[n]` 映射回真实 `chunk_id`，无法映射的一律丢弃并记入日志。
- 输出必须过一遍数字检查：答案中出现的金额/日期/数量，必须在引用原文里能**逐字**找到。找不到 → 判定为可疑，按拒答处理（R6）。
- 每条问答都要落结构化记录：`question`、`retrieved_chunk_ids`、`answer`、`cited_chunk_ids`、`refused`、`degraded`、`cost_cny`、分段耗时。

## 五、拒答

- 拒答是**正常业务结果，返回 200**，不是错误。用结构化字段表达：
  ```json
  { "refused": true, "reason": "no_evidence", "answer": "根据现有资料，我无法回答这个问题。" }
  ```
- 拒答判定必须可解释：记录"为什么拒"（无候选 / 分数低于阈值 / 模型自判无依据），三种原因要能分开统计。
- **拒答率与误拒率必须成对监控**。只看拒答率会诱导系统变成"什么都不敢答"；只看误拒率会诱导它变成"什么都敢答"。

## 六、LLM 网关

- 所有模型调用（Chat / Embedding / Rerank）统一走网关，网关负责：超时、重试（2 次，仅幂等请求）、熔断、降级、并发限流、Token 记账。
- **超时按 provider 配置，不设全局硬默认值**：云端 chat API 常用 15—30s，本地小模型（CPU 推理）需 120—300s。**禁止把某一类的经验值当成所有 provider 的默认值**——15s 对本地 7B 必然超时，120s 对云端则是白等两分钟。取值依据与升级路径见 `app/core/llm_gateway.py` 的 `chat()` 注释。
- **网络类错误才重试**（超时、5xx、连接失败）。业务类错误（400、内容审核拒绝）**不重试**。
- 任何一次模型调用失败，都必须让上层拿到明确的失败原因，**不准吞掉异常返回空字符串**（R7）。
- 主模型不可用时降级到备用模型；降级必须上报 `degraded=true`，并在响应里体现。

## 七、评估

- 评估集三件事绝对不可动，除非单独提交并写明理由：**删除题目、修改标准答案、改 `should_refuse` 标记**（R13）。
- 评估必须能被复现：跑评估时记录模型版本、提示词版本、分块参数、检索参数。**换过任何一个都要记**，否则两次评估数字不可比。
- 新指标一律先加为**软门禁**（`docs/quality-gates.md`），连续两个迭代稳定达标后再升级为硬门禁。
- **先有基线，再谈优化**。没有基线的"优化"无法证明有效，也无法证明没有把别处改坏。

# ADR-0010：对象存储实现由 MinIO 官方镜像改为 silo（MinIO 社区延续）

- 状态：已采纳
- 日期：2026-10-14
- 决策人：（你的名字）

---

## 一、背景

技术栈原定对象存储用 MinIO（S3 兼容），T11 实施"原文 + 解析文本落对象存储"时，
发现**官方镜像已无法获取**：

| 探测 | 结果 |
|------|------|
| `docker manifest inspect minio/minio:*` | MISSING |
| Docker Hub `minio/minio` | 404（仓库已被删除） |
| `quay.io/minio/minio` | 401 UNAUTHORIZED |

上游行为（非网络问题）：MinIO Inc. 于 2025-10 停止发布 Docker 镜像与预编译二进制，
2026-02 归档了 `minio/minio` 仓库。

约束不变：**单人开发、Docker Compose 单机部署、数据不出内网、预算极低、无专职运维。**
对象存储的职责很小——存原文与解析文本两类对象、桶私有、通过后端访问。

---

## 二、备选方案

| 方案 | 一句话说明 | 好处 | 代价 |
|------|-----------|------|------|
| A. **silo（MinIO 社区延续）** | PGSTY 维护的 MinIO drop-in 替代，命令与服务结构一致 | S3 接口一致，代码几乎零改动；本机已预置镜像；实测通过 | 社区维护而非商业公司，长期维护存疑 |
| B. 第三方镜像源拉冻结版 MinIO | 拉最后一个官方版 `RELEASE.2025-09-07T16-13-09Z` | 名义上仍是 MinIO | 镜像源不可控；版本永久冻结、不再有安全更新；官方仓库已归档 = 技术债 |
| C. 换 SeaweedFS / Garage 等 | 换一个其它 S3 兼容实现 | 上游活跃 | 偏离原技术栈最远，本机未预置，需重新验证一套，工作量最大 |

---

## 三、决策

选定：**A. silo（`pgsty/silo:RELEASE.2026-08-06T00-00-00Z`）**

---

## 四、理由

结合本项目的实际约束，而不是泛泛的"性能好、生态好"：

1. **职责面极窄**：本项目只用到 put/get/建桶/列对象，S3 协议保证行为一致，
   换实现对业务代码的影响被 S3 接口这一层挡住了。
2. **迁移成本近零**：silo 是 MinIO 的延续，命令行结构（`server` / `healthcheck`）、
   环境变量（`MINIO_ROOT_USER`）、健康端点（`/minio/health/live`）都一致，
   团队已有的 MinIO 知识全部可复用。
3. **已在本机验证，不是纸面比较**：`/minio/health/live` → 200；
   `--console-address ":9001"` → 控制台 200；
   `minio` Python SDK 的 `make_bucket` / `put_object` / `get_object` / `list_objects`
   全部正常，往返内容一致。
4. **保留了"以后迁阿里云 OSS 不改代码"的原设计意图**：
   `app/core/storage.py` 只依赖 S3 接口，换后端只改 endpoint 与密钥。

---

## 五、代价（必填，不允许留空）

1. **维护主体是社区，不是公司**：若 silo 上游将来也停止发布，
   需要自行从源码构建镜像（AGPLv3，自用不分发，合规上可行）。
2. **功能面小于原版 MinIO 的全部能力**：本项目当前用不到 IAM/STS、S3 Select、
   对象锁等高级特性；一旦需要，silo 未必支持。
3. **许可为 AGPLv3**：自用无分发因此无风险，但将来若把服务分发给第三方需复核。
4. **文档口径变更成本**：全仓库"MinIO"字样需要说明含义——
   **技术栈层已明确实现为 silo；架构图与数据流表中的"MinIO"作为
   "S3 对象存储角色"的通俗代称保留**（silo 与其产物、接口一致）。

> 什么情况下会后悔：把对象存储当成了"必须用商业公司产品"的依赖项，
> 或者将来需要 MinIO 独有的企业特性时，才会觉得当初该另选。

---

## 六、复核条件

满足任一条时应重新评估本决策：

1. silo 上游连续 **6 个月**未发布新镜像 / 二进制；
2. 需要 MinIO 独有特性（IAM/STS、S3 Select、对象锁、多租户）而 silo 不支持；
3. 需要迁往云端对象存储（阿里云 OSS）时——这本就在计划内，届时只改 endpoint 与密钥。

---

## 七、作为不懂技术的人，我只需要确认哪一点？

> 你只需要确认这条：**"对象存储将由 MinIO 的社区延续项目 silo 提供，
> 接口与 MinIO 一致、现在能用，但它的长期维护依赖社区而非公司；
> 若社区项目也停更，我需要自己构建镜像。"** 你能接受，就按本决策执行。

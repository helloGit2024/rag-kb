# 约束条件清单（constraints.md）

> **这份文件是后面所有决策的输入。** 它不描述"要做什么"，
> 只描述"在什么限制下做"——而限制往往比需求更能决定方案。
>
> 这份实例里的数值是按"一个人 + AI、公司内部使用"的典型情况推演的。
> **凡是标 `⚙️ 待你确认` 的，都要换成你的真实情况。**

---

## 一、要解决的具体问题

公司内部文档已经累积到 3000 多份（制度、产品资料、技术文档、客户案例），
散在内网共享盘和 OA 里，没有统一入口、没有全文检索。
员工找一个具体条款平均要花 8—15 分钟，经常直接问同事，导致同一个问题被反复回答。
我们希望：**用自然语言提问，10 秒内拿到答案，并且能看到答案来自哪份文档的哪一段。**

> 注意这不是技术方案，是问题描述。反例："我要做一个 RAG 系统，用 pgvector 存向量。"
> 那是方案——而方案应该由约束推出来，不应该写在约束里。

## 四、硬约束（最重要的一节）

| 约束项 | 内容 | 说明 |
|--------|------|------|
| **数据合规** | 文档原文**不得出内网**；可调用云端大模型 API，但**只允许传检索到的片段**，且必须经脱敏 | 这条最硬：它直接排除了"把原文喂给云端"的方案，也决定了嵌入模型必须本地部署 |
| **月度预算** | ≤ ¥1500 / 月（含模型调用与服务器）（`⚙️ 待你确认`） | 决定模型选型：不能用 GPT-4 级别做大范围回答 |
| **可投入时间** | 每周 10 小时（工作日晚上 + 周末） | 决定 V0.1 必须极小 |
| **上线时间要求** | 6 周内要有**可演示版本**给领导看；12 周内要能试点 | 决定 V0.1 必须只做一条能跑通的链路 |
| **规模上限** | 文档块 ≤ 30 万，同时在线 ≤ 20 人 | 决定 pgvector 够用，不需要独立向量库 |
| **人力** | **1 人（我）+ AI 编码工具**，无运维支持 | 决定不能上 K8s、不能拆微服务 |
| **我的技术能力** | 懂 RAG 算法；不会前端、不会后端、不会 Docker/K8s、不会写 SQL | 决定方案必须极度收敛 |

## 五、我完全不会的技术（如实写）

- 不会配置 Linux 服务器，不会用命令行运维
- 不会写前端页面（React/Vue 都没用过）
- 不会用 Docker——听说过，但不知道容器和镜像的区别
- 不会写 SQL，只会 `SELECT * FROM t`
- 不会配置 Nginx、证书、域名解析

> **这一节不能写"我大概都能学"。** AI 会据此决定方案的复杂度：
> 你写"不会 Docker"，它会给你 `docker compose up` 一条命令搞定；
> 你写"我会 Docker"，它会给你一个需要你自己编排的 K8s 清单。

## 六、我手上有什么资源

- 一台开发用的 Mac（M2 / 16 GB），性能一般
- 一台内网服务器：8 核 CPU / 32 GB 内存 / **无 GPU**，已装 Ubuntu（`⚙️ 待你确认` 能否长期占用）
- 公司已有云大模型 API 配额（可用于测试；生产受合规限制）
- 同事懂后端，但只能偶尔帮忙看一眼，不能指望
- 共享盘有只读权限，可取文档但**不能改动原目录**

> **无 GPU 这一条很关键**：它意味着 bge-m3 本地推理会慢（CPU 推理约 100—300ms/条），
> 因此"批量向量化"必须是离线任务，且要限流——这直接推导出 `AGENTS.md` 的硬规则 R10。

## 七、我懂什么（决定哪些决策由我拍板）

- **我懂 RAG 算法**：分块策略、混合检索、RRF 融合、重排序、查询改写、
  拒答判定、忠实度衡量——**这些由我判断**。请给我 2—3 个方案 + 明确推荐 + 数据对比，
  **不要替我决定，也不要让我从零权衡。**
- **我不懂前端后端工程**：技术栈、目录结构、部署方式、CI 配置——
  **请直接给我推荐并说明代价**，不要让我在选项里挑。

## 九、复核提醒

> 这份约束里，哪一条最容易随时间变化？变化后会影响哪些决策？

| 约束 | 变化可能性 | 变化后要重新评估什么 |
|------|-----------|-------------------|
| **数据合规放开**（允许原文出内网） | 中 | 架构可大幅简化：嵌入和生成都能用云端托管，不必自建推理服务；但成本上升 |
| **预算提高到 ¥8000/月** | 中 | 可用更强模型 → 但按经验，检索质量才是瓶颈，换模型收益不确定，需先跑评估对比 |
| **服务器分到 GPU** | 低 | 本地嵌入/重排速度提升 10 倍以上，批量入库时间从小时级降到分钟级 |
| **同时在线人数涨到 200** | 低 | pgvector 仍够用，但连接池、并发限流、缓存策略需要重新压测 |
| **文档量涨到 300 万块** | 低 | 触发 `docs/adr/0002` 的复核条件，需重新评估向量库选型 |

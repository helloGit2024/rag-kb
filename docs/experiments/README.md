# 优化实验记录（docs/experiments/）

> 每做一次优化（改分块、改提示词、换模型、调参数），就在这里新建一个文件记录。
> 文件名格式：`YYYY-MM-DD-优化项简述.md`
>
> **为什么必须记**：大模型应用有个特殊性质——**改动 A 经常让 B 变差，而且很难预判**。
> 没有对比记录，你的优化就是"我觉得变好了"，很容易做负优化。
> 本项目就发生过：把 top_k 从 5 提到 10，召回略升，但忠实度掉了近 6 个点、延迟涨 60%。

## 三条纪律

1. **一次只改一个变量。**
   同时改分块 + 提示词 + 模型，你会看到指标变化，
   但永远不知道是哪个改动带来的。

2. **必须先跑改动前的基线。**
   没有基线数字，改动后的数字无法解读。
   **建立基线是本项目 V0.1 阶段最重要的交付物之一。**

3. **一次改动的结果不达标，也要记录。**
   失败的实验同样是资产——它能阻止你（或未来的你）重复尝试同一个想法。
   特别值得记录的是"直觉上应该有用、实际是负优化"的案例。

## 优化杠杆的性价比参考

> 数据来自 RAG 项目的普遍经验。具体数值因项目而异，请在你自己项目上实测。

| 优先级 | 优化项 | 典型收益 | 代价 |
|--------|-------|---------|------|
| ① 最高 | 检索质量（分块策略、混合检索、重排序） | 端到端准确率 +15~30% | 中等 |
| ② 很高 | 提示词约束（强制依据资料、要求引用、明确拒答） | 幻觉率 -30~50% | 极低 |
| ③ 高 | 查询改写（口语化 → 检索友好） | 召回率 +10~20% | 低 |
| ④ 中 | 模型路由（简单问题用小模型） | 成本 -40~60% | 中 |
| ⑤ 中 | 缓存 | 成本 -20~40%，延迟大幅下降 | 低（**注意权限隔离**） |
| ⑥ 较低 | 换更大更新的模型 | 不确定，可能负收益 | 高 |

> **经验：不要先动模型。**
> 检索质量差的项目，换模型几乎没帮助——你给它的资料是错的，模型再强也答不对。
> 顺序是：**先修数据与检索 → 再改提示词 → 最后才考虑换模型。**

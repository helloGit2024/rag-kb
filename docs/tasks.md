# 任务清单（tasks.md）

> 拆分规则：
> ① 每个任务必须能被**单独验证**（做完就能测出对不对）；
> ② 代码改动量 20—150 行（超过就继续拆）；
> ③ 写清"涉及哪些文件"和"依赖哪个任务"；
> ④ 排序原则：**数据模型 → 数据管道 → 检索 → 生成 → 接口 → 界面 → 优化**（不要先做界面）。
>
> **使用方式**：每次让 AI 干活这样说：
> 「请读 AGENTS.md，然后实现 T05。做完停下等我确认。」
> **一次只做一个任务**——这是 AI 编程不出错的核心纪律。

> **T22b 的背景与修复方向**（详见 `OPEN-QUESTIONS.md` 第二节 #12）：
> `POST /documents` 的重名判重（409）查的是"该 KB 下已有同名有效文档"，
> 但 documents 行由 worker **异步**创建 —— worker 建行前再传一次，
> 两次都判为不重名、都 202、最终入库两行。
> 修复方向二选一（实施前再定）：① worker 侧落 documents 行前按
> `(kb_id, title, is_active)` 二次查重，命中则复用/跳过；
> ② 上传端对 `(kb_id, file_md5)` 建唯一约束（R8：先加字段后约束，需迁移）。
> ★ 涉及上传链路 + worker + 可能加 DB 约束，属高风险改动，动手前先切分支。

> **T22c 的背景**（详见 `OPEN-QUESTIONS.md` 第二节 #7）：
> ① documents 行由 worker **异步**创建，上传接口不知道将来是谁建的
> （`perm.user_id` 从未进过 worker），故列表 `uploaded_by` 恒为 `null`
> （契约里却是 string）；② 上传不接受契约里的 `title` 表单字段 ——
> 现有 `title` 由 filename 推得，且 `validate_metadata` 还从 filename 推
> `source_type`，要支持自定义 title 必须改 `ingest_document` / worker 签名。
> ★ 两项都要动**同一条入库链路**，合并为一张任务一起改，只付一次代价；
> payload 增字段向后兼容。

## 六、顺序风险提示（顺序颠倒会返工）

| 任务对 | 顺序不能颠倒的原因 |
|--------|-----------------|
| T02 → 一切 | 数据模型定不下来，后面每个任务都要改表 |
| T03（分块）→ T04（向量化） | 分块策略一变，所有向量都要重建。**分块参数要在向量化之前定** |
| T05（检索）→ T07（生成） | 检索没通就做生成，你无法判断是"没找到"还是"没答好" |
| T14→T15（权限）→ T16（缓存） | 先有权限过滤，缓存才有东西可隔离。反过来做，缓存会污染权限 |
| T15/T17（权限）→ T25—T27（前端） | 权限没做对就做界面，界面上会先出现越权内容 |
| T28—T31（评估）→ 任何优化 | **没有基线数字，优化就是玄学**。这是最容易违反、代价最大的一条 |
| T42（重排）→ T43（查询改写） | 两者都改检索结果，同时上无法归因是哪个带来的提升 |
| T59（配置表）→ T60（CRUD 接口）→ T61（保存前测试） | 表没定就写接口 → 接口字段名会自己发明；没有 T61，脏配置会直接进库 |
| T60/T61（配置可管理）→ 任何换模型的对比实验 | 配置不能改之前，每次对比都要改代码重新发布，你会因为麻烦而放弃做对比 |
| T33（评估入库）→ T28/T31（评估脚本与基线） | 结果没地方存，基线就只存在于你的记忆里；V1 再补表等于把"基线说不清"拖到最需要它的时候 |
| T62—T64（数据集元数据 + active 门槛）→ T56（评估集扩到 100 条） | 没有元数据与门槛就扩集，会得到一批"未经确认就进了门禁"的题目，而门禁失去意义是完全静默的 |
| T66（只跑检索的对照路径）→ T67（归因确认） | 没有 `retrieval_hit` 这个布尔值，人工确认就退化成"凭感觉选一个原因"，准确率与自动分类器相当 |
| T54（反馈落表）→ T68（BadCase 闭环）→ T69（promote） | 反馈表没通，BadCase 没有来源；promote 若先于 BadCase 表，题目会从"未经确认的反馈"直接进题库 |
| T68/T69 → T56（把线上失败补进评估集） | 回灌通道没建好就扩集，你只能继续拍脑袋想题 —— 评估集会一直脱离真实用户踩的坑 |
| **T71（路由基线）→ T72—T80 全部** | 路由分不开的话，后面九个任务全都白做，而且你会**在两个月后才发现**。这是唯一能让你提前止损的任务 |
| **T72（语义层）→ T75（生成 SQL）** | 语义层没成型就调提示词，你会在"补语义层"和"改提示词"之间来回折腾 —— 而前者才是根因，提示词变不出没声明过的字段 |
| **T76（五道闸门）→ T77（真执行）** | 先接执行再接校验 = 有一段时间数据库是裸奔的。**顺序颠倒的代价不是返工，是事故** |
| **T79（固定 seed 库）→ 任何 SQL 指标** | 对着生产库跑评估 = "今天 100 分、明天 60 分"，而你会以为是模型不稳定 |

# 自动评分裁判提示词（evals/judge-prompt.md）

> 这份文件是**用来喂给裁判模型**的提示词模板，不是给人读的说明。
> 说明见 `evals/README.md` 第五节。
>
> 使用方式（`app/eval/judge.py` 中的调用逻辑，T29 起）：
> 1. 从 `golden_set.yaml` 取一条题（`judge: human` 的题直接跳过，进待人工评分清单）
> 2. 把 `{{question}}` / `{{expected_answer}}` 填进去
> 3. 把系统实际检索到的资料填入 `{{retrieved_context}}`
>    （编号格式必须与 `generator._build_context` 一致：`[n]（来源：《标题》）`，
>    否则答案里的 `[n]` 与资料编号对不上，引用准确率无从判定）
> 4. 把系统实际生成的答案填入 `{{actual_answer}}`
> 5. 用**与线上不同的、更强一档的模型**调用本提示词（模型名走环境变量 `JUDGE_MODEL`）
> 6. 解析返回的 JSON，累加各项分数（解析失败重试 1 次，仍败则该题维度置 null、不中断 run）
>

>   （R4：提示词必须独立成文件）。两份内容必须一致，改一处就要同步另一处。
>   v1/v2 保留在 `app/prompts/judge_v1.md`、`judge_v2.md`，仅作历史对照——

## 一、裁判提示词本体（system prompt）

```markdown
你是一名严格的 RAG 系统答案质量评审员。你的唯一任务是**逐维度打分**，
不是给一个笼统的总分。

## 背景

被测系统是一个企业内部知识库问答系统。它的硬性规则是：
1. 只能依据给定的资料回答，资料中没有的内容不得推测或补充
2. 每个事实性陈述后须标注来源编号，写作 `[n]`，n 是资料片段编号
3. 资料确实不足以回答时，必须输出固定拒答句式
4. 涉及数字须原文照抄，不得换算或四舍五入

## 你将收到四段输入

四段之间用 `<<<BEGIN>>>` 与 `<<<END>>>` 分隔，**不得跨段混淆**。

【输入一：用户问题】
<<<BEGIN>>>
{{question}}
<<<END>>>

【输入二：标准答案（出题人给出的必须包含要点）】
<<<BEGIN>>>
{{expected_answer}}
<<<END>>>

【输入三：系统实际检索到的资料（编号 [n] 与答案中的引用对应）】
<<<BEGIN>>>
{{retrieved_context}}
<<<END>>>

【输入四：被测系统实际生成的答案（**唯一评分对象**）】
<<<BEGIN>>>
{{actual_answer}}
<<<END>>>

【本题是否应拒答】{{should_refuse}}

⚠️ 最重要的三条区分：
- **输入二不是被测答案**，它是判分参照；
- **输入三不是被测答案**，它是资料原文；
- 只有**输入四**是被测答案。你评的是系统表现，不是资料或标准答案的表现。

## 评分前的强制核对（必须先做，结果写进 reasoning）

### A. 引用清单

1. 逐字扫描**输入四**，列出其中所有 `[n]` 形式的引用编号；一个都没有时写"无引用"。
2. 对每一个 `[n]`，在**输入三**中找到第 n 号片段，摘录能支持答案陈述的原文（至少 15 字）。
3. **禁止**在输入四明明含有 `[n]` 时声称"没有引用"或"未引用任何片段"——这是事实性错误，
   会直接导致引用准确率误判（Q015 实证：答案有 `[1]`，裁判却称零引用）。
4. 在 reasoning 的【引用核对】小节逐条写出：
   `[n] → 第 n 号片段原文：「……」→ 支持 / 不支持`

### B. 噪声隔离

1. 忠实度只检查**输入四里实际出现的陈述**能否在输入三找到依据。
2. 输入三可能包含与问题无关的噪声片段，这是正常现象；**无关片段不影响忠实度**。
3. **不得**因为输入三"没有提到某个主题"就判输入四不忠实。只有输入四**自己提到**了
   该主题、且在输入三中找不到依据时，才算不忠实。
4. 禁止用"未提及数据分级/外发审批/考勤/报销……"这类与输入四内容无关的主题作为扣分理由
   （Q015 实证：答案讲的是上线发布审批，裁判却以"未提及数据分级、外发审批"判 0.0）。

### C. 先定位，再判断

1. 对输入四的每一个事实性陈述，先在输入三中搜索关键词，确认命中的片段编号与原文。
2. 只有确认"所有片段都找不到依据"时，忠实度才可以是 0.0；只要有一处命中，
   忠实度至少为 0.5，并按命中比例给分。
3. 忠实度与引用准确率必须**分别核对**：
   - 陈述能在某片段找到依据 → 忠实度不受引用编号影响；
   - `[n]` 是否指向支持该陈述的片段 → 由引用准确率单独判定。
   不得因为"引用编号不对"就判忠实度 0.0，也不得因为"陈述有依据"就忽略引用错误。

## 你要评的五个维度

### 维度 1：忠实度 Faithfulness（0—1）

判定方法：**逐句检查输入四**中的每一个事实性陈述，
判断它是否能在**输入三**原文中找到依据。

- 所有事实性陈述都能找到依据 → 1.0
- 有 1 处找不到依据 → 0.5
- 有 2 处及以上找不到依据，或整体是编造的 → 0.0

📌 硬规则（优先于上面的扣分档）：
- 忠实度只评"输入四**说出口**的内容是否真实"，**不评它没说什么**。
- 输入四没说到的要点——无论输入二多么强调——一律**不在忠实度扣分**，
  只在完备性扣分。
- 若输入四的每一句陈述都能在输入三找到原文，忠实度**必须给 1.0**，
  即使它漏答了输入二的一半要点。

⚠️ 注意：不要用"这个说法符合常识"作为依据。只认输入三的原文。
⚠️ 注意：输入四比输入二"短"或"少讲了几点"属于**完备性**问题，
   不是忠实度问题，也不等于编造。
⚠️ 注意：判定时必须写明命中的片段编号与原文（如"输入三 [1] 原文包含……"）。
   输入三存在无关噪声片段，**不得**把"资料没提到某主题"当作不忠实（见 B 节）。

### 维度 2：答案相关性 Answer Relevancy（0—1）

判定方法：**输入四**是否回应了**输入一**真正在问的问题。

- 完整、直接回应 → 1.0
- 部分回应（如只答了多子问题中的一个） → 0.5
- 答非所问、绕圈子、答了相邻但不同的问题 → 0.0

### 维度 3：完备性 Completeness（0—1）

判定方法：对照**输入二**中标出的必须包含要点，计算**输入四**的覆盖率。

- 要点覆盖率 ≥ 90% → 1.0
- 60% ≤ 覆盖率 < 90% → 0.5
- 覆盖率 < 60% → 0.0

同时检查"不允许出现"的条目：**只要出现任何一条，本维度直接 0.0。**

### 维度 4：数字与事实精确性 Numeric Accuracy（0—1）

**本维度只对含数字、日期、金额的题生效；其他题返回 null。**

判定方法：逐个比对**输入四**中的数字与**输入三**原文。

- 全部一致，无四舍五入、无单位换算、无"约/大约/左右" → 1.0
- 有任何一处数字被改写、换算、模糊化 → 0.0

⚠️ 这是最容易被忽略的维度。特别注意：
   - "1204 万元" 写成 "约 1200 万元" → 0.0
   - "60 天" 写成 "两个月" → 0.0
   - "500 元/晚" 写成 "500 元左右" → 0.0

### 维度 5：引用准确率 Citation Accuracy（0—1）

判定方法：**先按 A 节列出输入四中的全部 `[n]` 编号**，
再检查该引用**所绑定的那个陈述**是否真的能被**输入三**中**第 n 号片段**支持。

- 所有引用绑定的陈述都被对应编号片段支持 → 1.0
- 部分引用正确（如引错编号、张冠李戴） → 0.5
- 任一引用绑定的陈述不被对应片段支持，或引用了不存在的编号 → 0.0
- 输入四含有事实性陈述、但完全没有任何引用标注 → 0.0
  （无从验证，且违反"必须标注出处"的硬规则）

⚠️ 注意：只看"陈述与第 n 号片段"的对应关系。
   陈述本身能在别的片段找到依据、但标注的编号不对 → 按引用错误处理（0.5）。
⚠️ 注意：输入四含 `[n]` 时，**不得**输出"没有引用标注"或"未引用任何片段"；
   必须先逐条核对并在【引用核对】中给出结论（Q015 实证）。

## critical_issue 的判定（严格按此，不要扩大）

`critical_issue` 只在下列三种情况下取值，**其余一律 null**：

1. `must_refuse_but_answered`：**仅当"本题是否应拒答=是"**，且输入四
   没有拒答（试图作答）。
2. `false_refuse`：**仅当"本题是否应拒答=否"**，且输入四拒答了。
3. `leaked_restricted_content`：输入四出现了输入三中没有、且明显属于
   其他权限范围的内容。

⚠️ **答得不完整、要点漏了几条、数字有误，都不是 critical_issue。**
   那些情况已经由 completeness / numeric_accuracy 扣分，不要重复归因。
   "本题是否应拒答=否"时，绝不允许输出 must_refuse_but_answered。

## 拒答题的评分

当【本题是否应拒答】= 是：

- 输入四**恰好**为固定拒答句式，且未输出任何库外内容 → 五维度均为 1.0
- 输入四拒答了，但附带了推测或常识补充 → 忠实度 0.0，相关性 0.5，其余 0.0
- 输入四**没有拒答**（试图作答） → 五维度均为 0.0，critical_issue 标
  `"must_refuse_but_answered"`

当【本题是否应拒答】= 否、但输入四拒答了：

- 五维度均为 0.0，critical_issue 标 `"false_refuse"`

## 输出格式（严格遵守：必须是合法 JSON，不要输出 JSON 以外的任何内容）

```json
{
  "faithfulness": 0.0,
  "answer_relevancy": 0.0,
  "completeness": 0.0,
  "numeric_accuracy": null,
  "citation_accuracy": 0.0,
  "reasoning": "逐维度说明判分理由，每个维度一句话，必须引用输入四的具体内容；末尾必须有【引用核对】小节，逐条写 [n] → 片段原文「……」→ 支持/不支持",
  "critical_issue": null
}
```

## 输出前自检（逐条打勾，再写 JSON）

1. 【引用核对】里每条都是"支持" → `citation_accuracy` **必须 1.0**；只要有一条"不支持"才可低于 1.0。
2. 输入四的每一句陈述都在输入三找到依据 → `faithfulness` **必须 1.0**；不得因为答案短、少列细节而扣。
3. 漏答输入二的要点 → 只扣 `completeness`，**不得**连带扣 `faithfulness` 或 `citation_accuracy`。
4. 输入四没有出现的主题 → 不得作为任何维度的扣分理由。
5. 自检结果与分数冲突时，**以自检为准**，回去改分数，不要保留矛盾。

## 三条禁令

1. **不要给总分。** 只给出五个分维度分数。
2. **不要因为答案"读起来很专业"就给高分。** 只看是否符合资料。
3. **不要在 reasoning 里写"总体来说不错"这类空话。** 每一句都要指向具体内容。

## 二、为什么这个提示词要这样写（逐条解释）

| 写法 | 为什么 |
|------|--------|
| 要求"逐句检查" | 否则模型会整体印象打分，漏掉中间某句的编造 |
| 明确"不要用常识作为依据" | 模型天然倾向用世界知识补全，这恰好是我们要测的幻觉 |
| 反例里给了三个具体改写例子 | 模糊标准会得到随机分数；具体例子能显著提高一致性 |
| 拒答类单独处理并区分"该拒未拒"和"误拒" | 这两种错误方向相反，混在一起统计会让指标互相抵消 |
| 禁止给总分 | 只给总分无法定位问题 |
| 要求 critical_issue 字段 | 让"越权"这类严重问题能被程序自动筛出来，进入人工复核队列 |
| 要求引用具体内容 | 空泛的理由无法用于归因（是检索问题还是生成问题） |
| 单独设"引用准确率"（T29 补） | 忠实度只管"陈述有没有依据"，不管"标注的编号对不对"；用户点开 `[1]` 发现原文对不上，是独立的一类失败，必须单列才能测 |
| 引用准确率里写明"无任何引用 → 0.0" | 不写这条，全文零引用的答案会拿满分——而那恰恰是最该扣分的形态 |
| 四段输入加 `<<<BEGIN>>>` 分隔（v2） | run 31 实测：14b 会把"资料"当成"标准答案"或"被测答案"（Q001 指责答案缺病假婚假、Q014 称答案内容是信息安全制度），层 2 指标被系统性拉低。加分隔符并在 Q014 对照实验中由 0.0 恢复到 1.0 |
| 显式传入"本题是否应拒答"（v2） | 让模型从标准答案文本自行推断不可靠：Q012/Q014/Q015 被误标该拒未拒，Q029 的固定拒答句被判幻觉 |
| 明确"答得不完整 ≠ 该拒未拒"（v2） | 背景规则"资料不足必须拒答"会被误用成扣分依据——漏讲要点应由完备性扣分，不是 critical_issue |
| 评分前强制列引用清单（v3 A 节） | v2 在 Q015 上四次稳定声称"答案没有引用"，而答案明明有 `[1]`；先枚举再核对，避免把事实性错误当评分依据 |
| 噪声隔离（v3 B 节） | Top-5 常含无关片段；v2 的 Q015 裁判被噪声块带偏，以"未提及数据分级/外发审批"为由判 0.0，理由与答案无关 |
| 先定位再判断（v3 C 节） | 要求先写出命中的片段编号与原文再给分；同时强制拆分忠实度与引用准确率，避免"引用错=陈述无依据"的连带误判 |
| 裁判上下文 ≥ 8192（v3 运行配置） | Ollama 默认 4096 会把 8.9k 字符的提示词中段截断，裁判看不到资料却照常打分；对照实验中同一提示词 4096 下引用 0.0、8192 下 1.0 |

## 三、人工校准方法（每轮评估必做）

1. 从 30—100 条结果中**随机抽 20—30 条**
2. 我自己按同样五个维度打分（不看裁判分数，避免锚定）
3. 计算偏差：

```
偏差 = 裁判判为"通过"但我判为"不通过"的条数 / 总抽查条数
```

4. 判断：

| 偏差 | 结论 | 动作 |
|------|------|------|
| < 10% | 裁判可信 | 继续用 |
| 10%—15% | 勉强可用 | 记录偏差，重写偏差最大的那个维度的评分标准 |
| > 15% | **裁判不可信** | 停用自动评分，先修评分标准；必要时改为人工评分 |

> **本项目当前状态**：
> - 偏差 8%（裁判可信）——该数字来自**四维度版本**的校准，不能直接套用到
>   现在的五维度版本上；
> - **五维度版本尚未完成人工校准**，v3 上线后必须按本节重做一次抽查，
>   重新记录偏差；在校准完成前，第 2 层分数只作观察、不作结论；
> - run 31（v1）已知缺陷：混淆输入段、误判该拒未拒 → 已在 v2 修复；
> - run 37—97（v2）Q015 稳定误判（四次理由逐字相同）：裁判称答案"没有引用"，
>   并以"未提及数据分级/外发审批"为由判忠实度 0.0；
> - **Q015 根因已用对照实验确认：裁判上下文 4096 不够**。同一份 v3 提示词
>   在 `num_ctx=4096` 下裁判凭空编造出 `[1]/[2]` 和两段不存在的原文；
>   在 `num_ctx=8192` 下 `[1]` 正确指向块 4619，引用准确率 0.0 → 1.0。
>   因此裁判模型必须使用 8192 上下文的派生模型（`.env.example` 有创建命令），
>   否则提示词中段被截断，任何措辞优化都无效；
> - v3 另加 A/B/C 三节强制核对，并在忠实度里补了"漏答要点不算不忠实"的硬规则
>   （4096 截断会放大成"资料里没有"的误判，8k 下仍可能把完备性混进忠实度）；
> - Q012 在 run 97 已恢复正常（引用准确率 1.0），无需再作为已知误判；
> - Q029 已由 runner 的 `should_refuse=true` 跳过裁判规则修复（commit 81e66eb），
>   不再由裁判判定，v3 无需重复处理；
> - 上一次校准发现的问题：裁判对"多子问题只答一半"的判定偏松
>   （给了 1.0 而人工判 0.5），已在判分规则里补充了"多子问题"的说明。

## 四、哪些题必须走人工评分（不交给裁判）

| 类型 | 示例 | 为什么 |
|------|------|--------|
| 权限判断 | Q019—Q021 | 是否越权必须人工确认，模型裁判可能"觉得答案很合理"就放过 |
| 涉及精确数字 | Q008、Q011、Q030 | 裁判容易忽略细微的数字错误 |
| 我自己也拿不准的 | Q027（时间错配） | 先人工定标准答案，再进评估集 |
| 主观题 | 无 | 本项目没有这类题 |

**处理方式**：在 `golden_set.yaml` 里给这类题加 `judge: human` 字段，
`app/eval/runner.py` 遇到该字段则跳过裁判，并把题号列进报告的
`pending_human_judge` 与 stdout 的"待人工评分"清单。

> 注意三条**自动**跳过规则（不依赖 `judge` 字段）：
> `permission` 与 `refuse` 类题本来就不跑裁判（用程序断言，见第五节）；
> `should_refuse: true` 的题也不跑裁判（2026-10-22 起，Q029 实证：正确拒答
> 被裁判五维打 0 并拉低 layer2 平均——拒答对错由程序断言与拒答正确率指标
> 负责，内容五维只评"该答且答了"的题）。即只有非应拒的 `normal` / `edge`
> 才可能进裁判。Q027 属于 refuse 类，即便不标 `judge: human` 也不会被裁判——
> 标注是为了让"这题需要人看"这件事显式可见。

## 五、成本控制

裁判模型调用会消耗 Token。控制方式：

- 只对 `category in [normal, edge]` 且非应拒（`should_refuse=false`）的题跑自动裁判
- `permission` 类用程序断言（检查响应体不含特定文档片段）→ 零成本、更可靠
- `refuse` 类与应拒题用程序断言（检查答案是否恰好等于固定句式）→ 零成本，但需人工抽检
- `judge: human` 的题跳过裁判 → 零成本，进待人工评分清单

V0.1（31 题）的实际账：normal 18 + edge 3 = 21 条候选，
扣除 Q028（超长题走 schema 校验、不打链）、Q008/Q011/Q030（`judge: human`）
与 Q029（应拒，不送裁判），**实际裁判调用 16 次**（约占 52%）。成本可忽略。
**能用规则判断的，不要用模型判断**——这是省钱最快的办法。
